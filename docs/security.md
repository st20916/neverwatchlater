# 보안 (Google OAuth · 토큰 · 시크릿)

> 이 문서는 `client`/`server` 어디에서 작업하든 **공통으로 적용되는 보안 규칙**입니다.
> 인증/시크릿/토큰/세션/로그와 관련된 코드를 작성·리뷰하기 전에 반드시 먼저 읽고 따라야
> 합니다. 팀 공통 코딩 컨벤션은 [`CONVENTIONS.md`](../CONVENTIONS.md)를 참고하세요.

---

## 1. 시크릿

- 시크릿 값은 저장소에 **절대** 들어오지 않는다. 로컬은 `.env`, 배포는 배포 플랫폼 시크릿 저장소.
- 새 환경변수를 도입하면 `.env.example`에 **키 이름과 설명만** 추가한다.
- 에이전트는 `.env`, `*.pem`, `client_secret*.json`을 열거나 수정할 수 없다 (훅이 차단).
  값이 필요하면 사용자에게 요청한다.
- 시크릿이 커밋에 섞였다고 의심되면 즉시 중단하고 사용자에게 보고한다. 스스로 이력을 다시 쓰지 않는다.

## 2. Google OAuth

- 인증 코드 교환은 서버에서만 한다. 클라이언트 시크릿이 브라우저로 나가지 않는다.
- 필요한 최소 범위(scope)만 요청한다. 범위를 추가할 때는 이유를 [`product-specs/auth.md`](./product-specs/auth.md)에 적는다.
- 토큰 저장: 액세스 토큰은 단기 보관, 리프레시 토큰은 암호화 저장. `TODO(확정필요)`: 저장·암호화 방식.
- 토큰 갱신은 `providers/google-oauth` 한 곳에서만. 도메인 코드는 갱신 로직을 알지 못한다.
- 사용자가 연동을 해제하면 저장된 토큰과 파생 데이터를 삭제한다.

## 3. 세션

- 세션 쿠키는 `HttpOnly`, `Secure`, `SameSite=Lax` 이상.
- 상태 변경 요청은 CSRF 방어를 갖는다.
- 로그인·로그아웃·권한 변경은 감사 로그(구조적 로그)로 남긴다. 토큰 값은 남기지 않는다.

## 4. 로그·에러

- 토큰, 인증 코드, API 키, 이메일 원문을 로그·에러 메시지·클라이언트 응답에 넣지 않는다.
- 외부 오류를 사용자에게 그대로 전달하지 않는다. 내부 상세는 서버 로그에만.

## 5. 사용자 데이터 최소화

- 서비스 목적에 필요한 것만 저장한다(영상 ID, 제목, 채널, 추가 시각, 요약).
- 삭제 요청 경로를 갖는다. 삭제는 파생 데이터(요약 캐시 포함)까지 포함한다.
- 요약을 위해 외부 AI 공급자로 보내는 데이터 범위를 [`product-specs/ai-summary.md`](./product-specs/ai-summary.md)에 명시한다.

## 6. 의존성

- 새 의존성은 필요·유지보수 상태·설치 크기를 확인하고 추가한다. 추가 이유를 커밋 메시지에 남긴다.
- 락파일은 도구가 갱신한다. 손으로 편집하지 않는다 (훅이 차단).
